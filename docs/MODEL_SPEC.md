# Dark Ascent · Формат 3D-моделей

По этому документу делается весь контент для 3D-отрисовки: герои, мобы, NPC, оружие и предметы окружения. Один файл — одна модель. Пример-эталон каждого вида лежит в `js/render3d/models/`. Стиль (палитра, пропорции, обводка, свет) описан в `docs/ART_BIBLE.md`, числа — в `js/render3d/style.js`.

Проверка файла одной командой: `node tools/check_models.mjs <id>` (без аргументов — все модели). Проверка глазами: `index.html?render=3d&spawn=<тип врага>` (мобы появляются в деревне рядом с героем).

## 1. Принципы
- **Процедурно, без внешних ассетов.** Геометрия строится кодом, цвет задаётся цветом вершин (`part()` рисует градиент «низ темнее, верх светлее»), а **рисованная фактура** выбирается опцией `tex` (раздел 4): она генерируется на canvas при загрузке и ложится triplanar, UV не нужны. Сборка остаётся лёгкой, а Яндекс Игры не видят чужих файлов.
- **Формы с фасками и деталями.** Не голые примитивы: `bbox` (бокс с фасками), `lathe` (тело вращения: кирасы, поножи, черепа, бочки), `tube` (сужающаяся трубка: рога, рёбра, когти, корни), заклёпки, ремни, каймы. Лёгкая кривизна — `geo.warp`.
- **Модель ничего не импортирует.** Всё нужное приходит аргументом `build(kit)` (раздел 4). Так файл не зависит от устройства движка.
- **Модель отвечает только за вид.** Урон, ИИ, коллизии, перемещение — в `js/game`. Модель не знает про игру: ей дают позу (клип и прогресс), она двигает свои кости.
- **Единые имена клипов и сокетов.** Благодаря этому враг, герой и NPC подключаются к игре одинаково, а оружие меняется между героями.

## 2. Где лежит и как подключается
```
js/render3d/models/
  hero/<класс>.js          warrior.js   (ключ реестра = класс героя из js/data/items.js CLASSES)
  mob/<тип>.js             skel_warrior.js, ghoul.js   (ключ = тип врага из js/data/enemies.js ENEMIES)
  npc/npc_<имя>.js         ключ = поле model у NPC в assets/maps/*.json (_villager.js — общая заготовка, не модель)
  weapon/<имя>.js          sword_iron.js, shield_round.js …
  prop/<спрайт>.js         house_0.js, tree_1.js …   (ключ = spr из js/world/zone.js PROP)
js/render3d/registry.js    единственное место подключения: добавили файл — добавьте import и строку в нужную таблицу
```
Файлы с `_` в начале — общие заготовки, в реестр не попадают.

## 3. Контракт файла
```js
export default {
  id: 'skel_warrior',          // = имени файла и ключу реестра
  kind: 'mob',                 // hero | mob | npc | weapon | prop
  outline: 'mob',              // ширина обводки из OUTLINE: hero | mob | stone | prop | small; false — без обводки
  build(kit, opts) { … return model; }
};
```
`build` вызывается один раз на каждый экземпляр (для `batch`-предметов — один раз на тип). Он создаёт новые объекты каждый раз; общие геометрии можно кэшировать внутри файла.

### Система координат и единицы
- Метры. Ось **+Y вверх**, начало координат — **на земле между стопами**, модель смотрит в **+Z**, её левая сторона — **+X** (щит на +X, меч на −X).
- Мир игры (x, y) → three.js `(x, 0, y)`. Камера смотрит с (+X, +Z) под 45°, то есть «лицом к игроку» стоит модель, повёрнутая в +X+Z.
- Высота героя 2,0 м при голове 0,5 м (1:4), мобы и NPC — по таблице в Art Bible, раздел 3.

## 4. kit — что есть у файла модели
| Поле | Что это |
|---|---|
| `THREE` | библиотека three.js |
| `part(geometry, color, pos, rot, scale, opts)` | поставить примитив, закрасить, вернуть геометрию. `opts`: `{ top: цвет верха, y0, y1, emit: true, tex }`. `emit: true` — самосвечение (глаза, руны, клинки Бездны), не зависит от света. `tex` — рисованная фактура: `wood` (волокна вдоль Y: столбы, рукояти), `woodH` (вдоль доски), `stone`, `roof`, `plaster`, `metal`, `cloth` (ткань и кожа), `bark` |
| `bbox(w, h, d, фаска, color, pos, rot, opts)` | бокс с фасками (блик на рёбрах вместо «пластилинового» куба) |
| `lathe([[r, y], …], color, pos, rot, scale, opts, сегменты)` | тело вращения по профилю |
| `tube([[x, y, z], …], r0, r1, color, opts, граней)` | сужающаяся трубка по точкам (рога, рёбра, когти), кончик закрыт |
| `merge([геометрии])` | слить в одну геометрию с общим цветом вершин; **всё статичное одной кости сливайте в один меш** |
| `ball(r, color, pos, scale, opts)` | сфера-шорткат |
| `group(pos, parent)` | `Group` в позиции внутри родителя (кость) |
| `pivot(root, y)` | пара `{ spin, body }`: ось падения/кувырка на высоте `y`; в покое всё стоит на земле |
| `mat({ rim, rimColor })` | материал персонажа (toon 3 ступени, rim-свет, вспышка удара, фактуры, затенение у земли). **Один на модель** — тогда движок сольёт все меши в один `SkinnedMesh` (раздел 5) |
| `propMat(def)` | материал предмета окружения (ветер `def.sway`, растворение между камерой и героем, rim `def.rim`, фактуры, затенение у земли `def.ao`/`def.aoH`) |
| `rig` | `clamp, smooth, easeOut, easeIn, lerp, footTarget, legIK` — IK ног и фазы шага (см. `js/render3d/rig.js`) |
| `geo` | `rng, fbm, noise, paint, place, jitter, spherify, chamferBox, warp, taperTube, lathe` — построители форм |
| `PAL, HERO, MOB, OUTLINE, RIM, FOLIAGE` | палитра и числа стиля из `style.js`: берите цвета оттуда |
| `Cape` | плащ на Verlet-физике (см. `models/hero/warrior.js`) |
| `scene` | сцена (нужна только для плаща) |

## 5. Персонаж: hero, mob, npc
`build` возвращает:
```js
{
  root,                        // Object3D, корень модели (ось и начало — по разделу 3)
  height, radius, shadow,      // м: рост, радиус для столкновений/полосок, размер блоб-тени
  materials: [mat],            // все материалы персонажа — нужны для вспышки при ударе
  sockets: { handR, handL, back, head },   // точки крепления (раздел 7)
  bones: { … },                // все подвижные Object3D по именам — для плавного перехода между клипами
  clips: { idle:{loop:true}, walk:{loop:true}, attack:{dur,hit}, hit:{dur}, death:{dur}, cast:{dur,fire} },
  anims: { idle(a), walk(a), attack(a), hit(a), death(a), cast(a) },
  defaultWeapons: { handR:'sword_rust', handL:'shield_bone' },   // необязательно: оружие по умолчанию (id из таблицы weapon)
  update(dt, t, env, actor),   // необязательно: вторичное движение (плащ). env.wind — Vector2
  dispose()                    // необязательно: убрать за собой объекты вне root (как плащ)
}
```
**Один вызов отрисовки на персонажа.** `Actor` после `build` сливает все меши модели с общим материалом в один `SkinnedMesh` с «жёстким скинингом» (`bakeRigid` в `actor.js`): каждая вершина привязана к своему исходному мешу как к кости. Анимации ничего об этом не знают — двигайте кости (`Object3D`) как раньше. Нельзя прятать части через `mesh.visible` (исходные меши выключены через `layers`); если часть должна исчезать, пометьте её `userData.noBake = true`.

**Обязательно** шесть клипов: `idle, walk, attack, hit, death, cast`. Необязательные: `dodge` (перекат героя), `talk` (разговор NPC), `run`, `attack2`, `slam`, `roar`, `special`. Если клипа нет, игра берёт ближайший: `run→walk, dodge→walk, talk→idle, attack2/slam→attack, roar/special→cast, stun→hit`.

### Клипы — сигнатура и правила
`anims.<клип>(a)` вызывается каждый кадр, пока клип активен, и **полностью записывает позу своих костей** (поворот, позицию, масштаб). Не рассчитывайте на предыдущий кадр: плавный переход между клипами (≈0,06–0,14 с) делает движок сам по списку `bones`.

Аргумент `a`:
| Поле | Смысл |
|---|---|
| `t` | общее время, с (дыхание, покачивания) |
| `dt` | длительность кадра, с (для фаз шага) |
| `time` | время в текущем клипе, с |
| `k` | прогресс разового клипа 0…1 (attack, hit, death, cast, dodge); у циклических не задан |
| `speed` | скорость по земле, м/с (для `walk`: шаг должен совпадать со скоростью, чтобы стопы не скользили) |
| `move` | `speed` нормированная на 0…1 |
| `combo` | 0/1 — чередование ударов комбо (зеркальный замах) |

**Момент удара.** В `clips.attack.hit` (и `clips.cast.fire`) модель указывает, на какой доле клипа `k` приходится удар (замах до него, выпад на нём, возврат после). Игра попадает по врагу в своё время (у меча 0,5, у моба `impact` в `enemies.js`), а движок растягивает время так, что кульминация вашего клипа совпадает с моментом урона. Поэтому ставьте `hit` честно, например 0,42.

**Смерть.** `death` при `k = 1` — конечная поза (тело лежит и остаётся лежать, пока игра не уберёт труп). Падение делайте через `pivot()`: `spin.rotation.x`, `spin.position.y`.

**Какой клип игра включает:**
| Состояние в игре | Клип | Прогресс `k` |
|---|---|---|
| стоит | `idle` | — |
| идёт/бежит | `walk` (`speed` — реальная скорость) | — |
| обычный удар, выстрел | `attack` | от анимации игры |
| заклинание, навык, снаряд мага/лучника | `cast` | от анимации игры |
| получил урон со стаггером | `hit` | от анимации игры |
| смерть | `death` | от анимации игры |
| уклонение героя | `dodge` | от анимации игры |
| NPC беседует | `talk` | — |

**Скелет и IK.** Ноги ходячих моделей собираются цепочкой «бедро → колено → голень → стопа» и двигаются `rig.legIK` по фазе шага `rig.footTarget`. Образцы: `models/hero/warrior.js`, `models/mob/skel_warrior.js`. Не-ходячие (парящий колдун) могут игнорировать IK.

## 6. Оружие и предметы в руках: `kind: 'weapon'`
```js
export default { id:'sword_iron', kind:'weapon', slot:'handR', reach:1.35, build(kit){ … return { root, materials:[mat] }; } };
```
- `slot`: `handR | handL | back | head` — в какой сокет надевается.
- Ориентация: **хват в начале координат, клинок/древко вдоль +Y**, плоскость клинка перпендикулярна X. Щит: центр в начале координат, **нормаль лицевой грани — +X**.
- Сокет героя уже повёрнут так, что меч в руке направлен вперёд-вверх; оружие ставится без поворота. Анимация может поворачивать сам сокет (`handR.rotation.x`), оружие едет вместе с ним.
- Смена оружия в игре: `actor.equip('handR', def)` / `actor.unequip(slot)`. Соответствие типа оружия игры (`wt`) и модели — `WEAPON_MODEL` в `registry.js`.

## 7. Сокеты (точки крепления)
`sockets` — обычные `Object3D` внутри костей модели, поэтому двигаются вместе с рукой.
| Сокет | Где | Для чего |
|---|---|---|
| `handR` | в кулаке ведущей руки (правая рука модели, −X) | меч, топор, посох, лук |
| `handL` | на предплечье/кисти левой руки (+X) | щит, второй клинок, факел |
| `back` | на спине между лопаток | двуручное оружие и колчан в ножнах |
| `head` | макушка | шлем, рога, нимб |
Героям нужны `handR, handL, back`. Мобам — по необходимости (`defaultWeapons` надевает оружие при создании).

## 8. Предмет окружения: `kind: 'prop'`
```js
export default {
  id:'house_0', kind:'prop',
  batch: true,                 // много одинаковых → один instanced-меш на меш модели (деревья, заборы, бочки). Нельзя вместе с update
  outline: 'stone',            // stone | prop | small | false (кроны обводки не имеют)
  sway: { base, amt, flutter },// ветер в вершинном шейдере: гнёт всё выше base
  rimColor, rim, side: 'double', // необязательно: цвет и сила rim-света (листве 0.12), двусторонние грани (листва)
  shadow: false,               // необязательно: не отбрасывать тень (мелкий декор)
  shadowProxy(kit) { … },      // необязательно: лёгкая геометрия, от которой рисуется тень вместо самой модели (кроны)
  ao, aoH,                     // необязательно: затенение у земли (0.62 к 0.9 м по умолчанию)
  leaf: 'leaf' | 'pine',       // необязательно: материал с текстурой листвы и альфа-вырезом (кроны из карточек, _foliage.js)
  receive: false,              // необязательно: не принимать тени (кроны)
  build(kit, opts) { … return { root, update?(t) }; }   // opts.color — цвет света, если рядом есть источник (портал)
};
```
- Начало координат — центр основания на земле. Размер по коллайдеру из `PROP` в `js/world/zone.js` (дом `house_0` — коллайдер 3,3×2,7 м, значит модель ≈ 2,9×2,3 м).
- Лицевая сторона — **+Z** (и боковая +X): камера смотрит с (+X, +Z).
- Тени: предметы отбрасывают тень солнца и принимают тени. Тень кроны рисуется от `shadowProxy` (слой 1 — его видит только камера тени).
- Декор земли (папоротники, цветы, камешки, грибы, кусты, пни, мешки, поленницы) в картах не стоит: его расставляет `PropLayer.scatterDecor` по тайлам карты; на низком качестве остаётся 35 %.
- Свет зоны (фонари, горны, порталы) задаёт `zone.lights`: движок сам добавляет ореол и пятно на земле, ближайшие два света становятся настоящими. В модели рисуйте только **самосвечение** (`emit: true`).
- Материал — `kit.propMat(this)`. Он растворяется дизерингом, когда предмет оказывается между камерой и героем.

## 9. Лимиты
Не нарушайте, чтобы телефон тянул (подробно — Art Bible, раздел 9). `check_models.mjs` ругается на превышение.
| Что | Лимит |
|---|---|
| Треугольников: герой / моб / NPC / оружие / предмет | 25 000 / 12 000 / 8 000 / 2 000 / 40 000 (реально: герой 5,1 тыс., скелет 5,4 тыс., упырь 3,1 тыс., житель ≈ 3,5 тыс., дом ≈ 6,6 тыс., дерево 120–550) |
| Предмет с `batch: true` (их сотни) | ≲ 1 000 треугольников (декор земли ≲ 350): каждый экземпляр рисуется, а с обводкой — дважды |
| Материалов на персонажа | 1 (`kit.mat`) — тогда весь персонаж = 1 вызов + обводка + тень |
| Мешей на персонажа | без ограничения по вызовам (сливаются при загрузке), но кости — только там, где что-то двигается |
| Внешние файлы, CDN | нет; фактуры — только из `textures.js` (генерация на canvas) |
| Реальные источники света, тени | модель их не создаёт |
| Цвета | только из `PAL`/`HERO`/`MOB` и производные; новый акцентный цвет — сначала запись в Art Bible |

## 10. Как добавить модель — чек-лист
1. Скопируйте ближайший по виду эталон, переименуйте `id`, поменяйте форму и палитру.
2. Подключите в `registry.js` (import + строка в таблице).
3. `node tools/check_models.mjs <id>` — должно быть `✓`.
4. Посмотрите в игре: враги — `?render=3d&spawn=<тип>[,<тип>]` (`&idle` — стоят на месте), NPC — по полю `model` в карте, предметы — на карте зоны.
5. Сверьте силуэт на телефоне (портрет 390×844) и читаемость: герой остаётся крупнее и светлее мобов.

## 11. Минимальный скелет файла (моб)
```js
export default {
  id: 'my_mob', kind: 'mob', outline: 'mob',
  build(kit) {
    const { THREE, MOB, part, merge, group, pivot } = kit;
    const mat = kit.mat({ rim: MOB.rim, rimColor: 0xffe2b8 });
    const root = new THREE.Group(), { spin, body: rg } = pivot(root, 0.5);
    const body = group([0, 0.9, 0], rg);
    body.add(new THREE.Mesh(merge([part(new THREE.CapsuleGeometry(0.25, 0.5, 4, 8), MOB.bone, [0, 0.3, 0], 0, 1, { top: 0xffffff })]), mat));
    const pose = (a, lean = 0) => { body.rotation.x = lean + Math.sin(a.t * 2) * 0.02; spin.rotation.set(0, 0, 0); spin.position.y = 0.5; };
    return {
      root, height: 1.6, radius: 0.35, shadow: 1.1, materials: [mat],
      sockets: {}, bones: { spin, body },
      clips: { idle: { loop: true }, walk: { loop: true }, attack: { dur: 0.6, hit: 0.5 }, hit: { dur: 0.25 }, death: { dur: 1 }, cast: { dur: 0.7, fire: 0.5 } },
      anims: {
        idle: a => pose(a), walk: a => pose(a, 0.1), attack: a => pose(a, 0.5 * Math.sin(a.k * Math.PI)),
        hit: a => pose(a, -0.4 * (1 - a.k)), cast: a => pose(a, -0.2 * a.k),
        death: a => { pose(a); spin.rotation.x = -Math.PI / 2 * Math.min(1, a.k * 1.3); spin.position.y = 0.5 - 0.3 * a.k; },
      },
    };
  },
};
```

## 12. Что формат пока не покрывает
- Настоящий скининг с весами (гибкая ткань, мягкие сгибы): сейчас «жёсткий» — каждая вершина целиком на одной кости. Один вызов отрисовки на персонажа уже есть.
- Броня и шлемы, меняющиеся по экипировке: сокет `head` и слои тела описаны, но в игре ещё не подключены (этап 3 плана).
- Спецэффекты (дуги ударов, снаряды, телеграфы атак): пока рисует 2D-наложение игры. Они переедут в 3D отдельным форматом.
- Анимированные предметы окружения без `batch` (портал) обновляются через `update(t)`; открытие дверей и сундуков (смена модели на лету) будет описано при переносе катакомб.
