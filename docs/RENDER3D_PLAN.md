# Dark Ascent · План переноса отрисовки на 3D

Стиль — `lab/three/torch.html` (`docs/ART_BIBLE.md`). Формат моделей — `docs/MODEL_SPEC.md`. Перенос идёт срезами: игра всё время запускается и играется, старая 2D-отрисовка доступна по `?render=2d`.

## Что остаётся, что меняется
| Остаётся без изменений | Меняется |
|---|---|
| Вся логика `js/game/*`: герой, ИИ врагов, бой, лут, квесты, сохранения | `js/render/renderer.js` (2D) перестаёт быть единственной отрисовкой |
| Мировые координаты в метрах, коллизии и поиск пути (`js/world/map.js`), сборка зоны из JSON (`js/world/zone.js`) | `js/core/iso.js`: `Camera` получила необязательную проекцию `proj` |
| DOM-интерфейс: HUD, окна, джойстик, мини-карта, подсказки | Спрайтовые атласы героя и мобов, предрендеренный пол (`assets/sprites`, `assets/maps/*_floor_*.jpg`): станут не нужны после переноса |
| `js/game/entities.js`: `Anim` и состояния остаются источником «какой клип и на каком прогрессе» | Генераторы графики `tools/art`: станут не нужны |

## Как устроено (то, что уже сделано)
```
js/render/index.js          выбор отрисовки: 3D по умолчанию, ?render=2d — старая; зона/класс без 3D автоматически идут в 2D
js/render/renderer.js       2D как раньше + renderOverlay(): прозрачный холст поверх 3D (полоски, цифры урона, эффекты, телеграфы)
js/render3d/renderer3d.js   WebGL: камера, свет, слой окружения, персонажи из состояния G; ничего в G не пишет
js/render3d/actor.js        Actor = модель + клипы + кроссфейд + поворот + вспышка + оружие в сокетах + тень; bakeRigid — модель в один SkinnedMesh
js/render3d/props.js        zone.statics → 3D (instanced для batch-предметов, отсечение по пирамиде видимости, заменители теней крон) + декор земли по карте
js/render3d/ground.js       земля по карте: рисованные текстуры по маскам типов, булыжник, вода (шейдер), трава пучками с LOD и тенями
js/render3d/post.js         постобработка: HDR-цель + MSAA, bloom, кривая тонов, цветокоррекция, виньетка
js/render3d/textures.js     рисованные фактуры, генерируются на canvas при загрузке (земля и материалы)
js/render3d/kit.js          «набор художника» для файлов моделей
js/render3d/registry.js     id → модель
js/render3d/models/…        сами модели; style.js, toon.js, geo.js, rig.js, cape.js — перенос из lab/three без изменения поведения
js/vendor/three.module.min.js   three.js локально (Яндекс запрещает CDN)
tools/check_models.mjs      проверка моделей по формату
```
Ключевые решения:
1. **Координаты.** Игра (x, y) → three `(x, 0, y)`; камера yaw 45° как в 2D, pitch 0,64 рад, дистанция 30 м, FOV 30° (раздел 4 Art Bible). Направление игры `dir` (0 = +x, шаг 45°) → поворот модели `π/2 − dir·π/4`.
2. **Одна проекция для всех.** Пока 3D активен, `G.cam.proj` подменяет `toScreen/toWorld`. Поэтому без правок продолжают работать: тап/мышь-прицеливание, подсказки обучения, привязка джойстика, 2D-эффекты. `cam.zoom` в 3D равен «пикселей на метр у цели / 45,25», так что 2D-эффекты совпадают по масштабу.
3. **Прозрачный 2D-холст поверх WebGL.** Полоски жизни, цифры урона, подписи, снаряды, частицы, телеграфы остаются в 2D до отдельного переноса. Недостаток: они рисуются поверх персонажей (без перекрытия стенами) и эллипсы на земле сплюснуты 0,5 вместо 0,6.
4. **Клипы ведёт игра.** Прогресс удара берётся из `entity.anim.prog`, момент попадания — из `act.impact`/`atk.impact`; движок растягивает клип так, что кульминация модели совпадает с уроном. Скорость ходьбы считается по смещению, стопы не скользят.
5. **Откат на 2D по зоне.** `supports(zone, profile)` в `renderer3d.js`: сейчас 3D только в деревне и для героя-воина. Остальное идёт в старую отрисовку, игра остаётся полностью рабочей.
6. **`lab/three` заморожен как эталон.** Игра не импортирует из `lab/` (папка не входит в сборку для Яндекса), общие модули скопированы в `js/render3d`. Править стиль теперь надо в `js/render3d/style.js`.

## Срез: что в нём есть и чего нет
Есть: деревня целиком по `assets/maps/village.json`, ~30 моделей по формату (герой-воин с плащом, скелет-воин, упырь, 4 NPC, меч/щит героя и нежити, дома, деревья, заборы, фонари, кузня и т. д.), оружие в сокетах, бой на настоящей логике игры, переключение 3D ⇄ 2D при смене зоны, портретный экран.

Нет (известные ограничения):
- Предметы окружения статичны: сундуки, двери, секретные стены меняют `d.spr` на лету, слой окружения этого пока не отслеживает (в деревне таких нет).
- Нет моделей для типов врагов кроме двух: остальные временно показываются скелетом-воином (в консоли предупреждение).
- Нет героев лучник и маг: для них игра идёт в 2D.
- Объекты на земле (лут) и метки интерактива рисует 2D-наложение.
- Тени есть только от солнца (одна shadow map); точечные огни теней не дают.
- Свет и постобработка настроены под деревню (`LIGHT.village3`); для катакомб нужен свой пресет.

## Доводка до уровня Torchlight (октябрь 2026)
Задание — `docs/PROMPT_3D_TORCHLIGHT.md`, референсы — `docs/reference/`. Сделано четырьмя шагами, после каждого — кадры и замер:
1. **Свет и постобработка:** shadow map солнца вокруг камеры, HDR + bloom + цветокоррекция + виньетка, AO по высоте, персонажи — один `SkinnedMesh` (draw calls упали с 254 до ≈ 160 вместе с проходом теней).
2. **Земля и растительность:** рисованные текстуры травы, глины, мха; рваные края троп; трава пучками с LOD и тенями; папоротники, цветы, камешки, грибы, кусты; вода; тени крон от заменителей.
3. **Материалы и окружение:** фактуры дерева, камня, дранки, штукатурки, металла, ткани, коры (triplanar по id вершины); дома с фахверком; фаски; хлам у домов.
4. **Герой и мобы:** латы героя, скелет с грудной клеткой, жилистый упырь, детальнее жители; герой крупнее (×1,1) и светлее.
Кадры: `docs/screenshots/3d_05…09_*.jpg` (до — `3d_01…04`).

## Замеры (Chromium, SwiftShader без GPU)
Draw calls — за весь кадр (тени + сцена + постобработка), треугольники — основной проход / тени.
| Кадр | Draw calls | Треугольники |
|---|---|---|
| До доводки: бой, высокое | 254 | 265 тыс. / — |
| Деревня с мобами, высокое, 1280×720 | 150–162 (лимит 260) | ≈ 340–348 тыс. (лимит 350) / ≈ 72–77 тыс. |
| Бой вблизи, высокое | 150 | ≈ 292 тыс. / ≈ 71 тыс. |
| Низкое (без теней, постобработки, 65 % декора) | 74 | ≈ 210 тыс. / 0 |
| Телефон 390×844 | 121 | ≈ 256 тыс. / ≈ 57 тыс. |
FPS на реальных Android не измеряли — нужен прогон перед релизом.

## Запуск и проверка
- Игра: `python3 -m http.server`, затем `index.html` (3D по умолчанию), `?render=2d` — старая отрисовка, `?render=3d` — то же, что по умолчанию, плюс логи переключения.
- Враги в деревне для проверки анимаций: `?spawn=skel_warrior,ghoul` (`&idle` — стоят на месте). Враги дерутся по настоящей логике.
- Деревня сразу: в консоли `import('./js/game/game.js').then(m => m.loadZone('town'))`.
- Проверка моделей: `node tools/check_models.mjs`.
